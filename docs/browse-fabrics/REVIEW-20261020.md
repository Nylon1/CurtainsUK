## Customer journey

The image-led introduction leads into visual colour and fabric-price choices. Selection feedback is immediate; removing a selection, removing several chips quickly, clearing a search and resetting cannot restore an old URL selection. Discrete choices use a 100 ms debounce; typed searches retain 300 ms. Existing cancellation and response-generation checks remain.

The opening now uses the existing room-inspiration photograph, layered fabric close-ups and a high-contrast collection button. The scene is labelled as inspiration with separate fabrics. Desktop and 390 px mobile review confirmed loaded images, readable captions, no horizontal overflow and the collection button scrolling to the filters. The room image has reserved dimensions and high fetch priority; no additional catalogue request or feature setting is introduced.

Each fabric keeps its original identity and destinations:

1. Discover it: photograph close-up, full fabric details and Room Visualiser where available.
2. Feel it at home: the existing sample action, including its eligibility and session handling.
3. Make it yours: the existing curtain configurator, subject to stock gates.

Ask Jane remains the fabric specialist, with the original fabric-specific adviser handoff. The close-up uses a native modal, keyboard zoom, Escape/Close and focus restoration. Zoom is illustrative, not a physical-scale claim. The larger photograph loads only when requested. The premium close-up adds labelled zoom buttons, a keyboard slider, Reset and separate pattern chips. Ask Jane uses a warm gold surface, conversation icon, hover lift, visible focus and reduced-motion support, retaining the original fabric-specific destination. Desktop and 390 px checks preserve readable actions and no horizontal overflow.

Fiona replaces the customer-facing Naila name and portrait. She is identified as an AI adviser, with an English-woman persona and British English retained. Existing internal identifiers, session storage, consultation routing and enablement flags remain unchanged. On mobile the same consultation panel moves after the results in DOM and keyboard order; desktop keeps it alongside.

The cards prioritise large View fabric, Room Visualiser, sample and Make curtains actions. The estimate sits in a compact disclosure under Make curtains, showing dimensions and lining when opened. The visible VAT phrase is removed, but the total still includes VAT. Browse reuses the existing sale banner and its existing enablement setting, without applying another discount.

## Example curtain price

Cards and close-ups show a pair for **100 cm total track width and 100 cm finished drop**, pencil pleat, standard lining, no interlining. This is not 100 cm per panel or a glass measurement. The total includes VAT once, excludes delivery and hardware, and remains an illustration rather than an order or quote token.

The server uses the active production making rules, actual fabric width and repeat evidence, and the same approved supplier-price selector as checkout. It does not multiply the public fabric guide to guess a curtain total. Missing or unsupported evidence displays “Price on configuration”. Existing availability gates still govern purchasing.

The owner subsequently approved changing the separate per-metre Browse guide from trade × 3 to trade × 2. Migration `20261020124923_browse_guide_two_times_trade.sql` preserves each existing guide reader's supplier selection and penny rounding, changes only its multiplier, and rebuilds the prepared generation under the existing transaction lock. The five displayed bands are under £30, £30–under £60, £60–under £100, £100–under £150, and £150+. Saved links keep their original pound boundaries and display a labelled saved range until changed. Matching uses the new guide amounts. The shared adviser guide readers also use the updated amounts. No extra VAT step or finished-curtain pricing change is introduced. The SQL test executes both readers and the existing full-refresh implementation, checks exact boundaries, rejected evidence, restricted access and repeat execution.

Approved price history is read in batches for at most 48 fabrics, with paginated promotion history and a bounded timeout. Price-read failure does not take browsing offline. No supplier costs enter the public card shape. Supplier prices, discounts and checkout rules are unchanged. The Browse-only guide migration was applied in the 20 October release.

The existing price bands still filter the fabric guide per metre, not the illustrative curtain total. The UI states that distinction.

- 34 focused tests passed across governed Browse filtering/guides, compact cards, selection races, production capabilities and production pricing. New estimate checks compare the exact production total, VAT allocation, width/repeat effects and missing-evidence behaviour.
- 22 existing HCI premium journey/integration/proxy-render checks passed during this candidate's work.
- The protected capability groups passed locally; the catalogue-hydration static assertion was preserved when concurrent reads were introduced. PR CI remains required.
- TypeScript passed with no emit. JavaScript syntax and Shopify theme validation passed.
- Candidate combined theme manifest validates 576 files, including the new Fiona portrait. This is a desired-source manifest, not a claim that live Shopify has those changes.
- Browser review at 390 px and desktop width verified no horizontal overflow, 44 px filter targets, mobile Fiona placement, original destinations, stock-restricted Make Curtains, modal dismissal/focus and rapid colour/chip changes.
- Read-only current database evidence for the captured first 24 identities produced 24 example totals. After the owner changed the example to 1 m by 1 m, recalculation from the captured approved evidence gives Abeja Ivory £240.00 for the stated pair. These are review-time examples, not permanent prices.
- The captured 24-card response is 52,812 bytes versus 125,758 bytes before, a 58% reduction despite adding curtain estimates. Gzip is 4,867 versus 13,502 bytes, a 64% reduction. These are payload measurements, not an assertion about live response time.

The controlled browser fixture injects latency to exercise races and uses captured public catalogue content and calculated review-time totals. It is not proof of live search counts, live availability, final API latency or a completed payment. No real sample order, consultation or checkout was submitted.

## Release outcome

At the review checkpoint, no live theme, production environment variables, stored settings, feature flags, database schema or supplier records had changed. Browse, advisers, Fabric Intelligence, visualisers and commerce retained their existing enablement.

The owner posted the required exact-current-head comment and both protected checks passed. The approved head merged into protected `b138f17e96b17c41e33f9052b12d6c5b20a0c155`. The scoped Vercel, Supabase and Shopify release and its live verification are recorded in `docs/PRODUCTION_SURFACES.md`. The guide migration committed direct definitions and the refreshed projection together. A rollback would restore the previous function/view definitions and run the existing full refresh in one transaction; it must not leave old prepared prices paired with new direct prices.
