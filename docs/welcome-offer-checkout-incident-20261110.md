# WELCOME5 mixed-cart checkout incident, 10 November 2026

The welcome popup, cart entry point and 5% review were released from protected commit `a7371f846d45e8302b7b90b0b4694cf512da277a`. The production sample-credit migration and six MAIN theme files were applied. A live guest curtain-and-cushion cart priced £670.66 of goods, £12.95 UK delivery and a £33.53 WELCOME5 saving, for £650.08 total. No payment or order was submitted.

The first unpaid handoff failed with `CUSHION_OWNER_MISMATCH`. The discounted My Home path persisted a derived checkout key while the hosted cushion draft receipt and creation claim used the original browser attempt key. PR #371, merged as `a2aa9dc295d69b3d7d0a58e2d6da57a8c16c07fa`, made both operations use the persisted group key. It also replaced an HTML-to-JSON parse error in the cart with a safe retry message. The API deployment is `dpl_9AkwDfJn5fhypdGaz93z3gqDN8xu`; the MAIN theme cart asset has MD5 `88f653fba4a6a4834c1e3f4bf4cf0156`.

A new-browser live retry at 10:57 UTC still failed after 26 seconds. Supabase logged a duplicate `cushion_checkout_groups` primary key on `commit_cushion_checkout`. The WELCOME5 key had been derived from the review and optional credit only. A fresh browser attempt with the same configuration therefore collided with the earlier group's globally unique key under a different owner. The cart preserved both items and displayed the safe retry message.

The follow-up change includes the random browser order attempt in WELCOME5's derived key. The same attempt retains one key on retry; a fresh attempt gets a distinct key even when the review is identical. The targeted regression covers both WELCOME5 with credit and without credit. Cushion and storefront suites, TypeScript and lint passed locally. Live unpaid handoff remains to be rechecked after this change enters the protected release and is deployed. Paid testing remains on hold.
